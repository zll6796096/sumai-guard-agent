# SumaiGuard Build 3 Xcode Cloud Release Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task in the existing repair worktree.

**Goal:** Produce, process, associate, and submit Version 1.0 Build 3 through a stable Xcode Cloud workflow without repeating ITMS-90111.

**Architecture:** Keep product code and backend behavior unchanged. The current macOS 27 beta host performs source validation and simulator tests only. Xcode Cloud performs the release archive, Apple-managed signing, and App Store Connect distribution with Xcode 26.6/iOS 26.5 on an Apple-supported production host. Apple processing, build association, App Review submission, approval, manual release, and storefront visibility remain separate gates.

**Tech Stack:** Xcode Cloud, Xcode 26.6 (17F113), iOS 26.5 SDK (23F81a), XcodeGen 2.45.4, SwiftUI, Firebase App Check/App Attest, Python 3.13 validators, GitHub, App Store Connect.

## Decision record

- **Real objective:** obtain an App Store-valid Build 3, not merely another local archive or upload attempt.
- **First-principles rule:** risk control and verifiable acceptance evidence precede speed; reuse LifeSnap Build 6's proven stable Xcode Cloud pattern.
- **Minimal verifiable deliverable:** Version 1.0 Build 3 produced by Xcode Cloud, accepted by App Store Connect without ITMS-90111, associated with the version, and submitted to App Review after action-time confirmation.
- **Likely tracked changes:** build identity and tests, automatic signing/team settings, generated Xcode project, Xcode Cloud manifest generated by Apple, release documentation, and this plan.
- **Out of scope:** product features, UI, backend/Cloud Run, Firebase policy, credential creation, local release archive/upload, automatic public release, or storefront claims.
- **Current release constraint:** macOS 27 Beta 5 is not a supported host for Xcode 26.6 App Store archives. Local checks remain diagnostic only.

## Acceptance criteria

- Local baseline and scoped release tests pass.
- Source and generated project both report version `1.0`, build `3`, team `YMUG864233`, automatic signing, and bundle ID `com.zll.sumaiguard`.
- Xcode Cloud is connected to the exact GitHub branch and shared `SumaiGuard` scheme.
- The workflow explicitly uses Xcode 26.6 and an Apple-supported production macOS image.
- Xcode Cloud completes archive/sign/distribution successfully and App Store Connect records Build 3.
- Apple processing finishes without `Invalid Binary`, `Rejected`, or a new ITMS-90111 notification.
- Build 3 is associated with Version 1.0.
- A separate action-time confirmation is obtained immediately before final App Review submission.
- Manual release remains enabled; approval, release, propagation, and storefront visibility remain pending gates.

## Risks and guardrails

- Do not archive or upload Build 3 from the current macOS 27 beta boot volume.
- Do not choose Xcode 27 beta; Apple currently allows it only for TestFlight.
- Do not invent or hand-edit Xcode Cloud manifest IDs; accept only IDs generated by Apple/Xcode Cloud.
- Use Apple-managed automatic signing with team `YMUG864233`; do not create/export signing credentials.
- If Apple requests login, passkey, Touch ID, GitHub authorization, or 2FA, pause for the user.
- Preserve unrelated work; stage only explicit paths and never use `git add .`, reset, stash, or broad clean commands.
- If the stable cloud Build 3 receives ITMS-90111, stop and open Apple Developer Support with exact cloud-build metadata. Do not guess with Build 4.
